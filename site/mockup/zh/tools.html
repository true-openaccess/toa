参考工具 toa

跨平台单文件工具（Windows / Linux / macOS），实现 TOA 0.1 哈希、核对、定稿、发布与取对象（MIT 许可）。

尚未发布 toa 0.1.0 (TOA 0.1)

暂未发布预编译包，请按以下步骤从源码编译（需数分钟）。

1从源码编译

需 Rust 1.85+ 与 cargo（可通过 rustup 安装）：

git clone https://github.com/true-openaccess/toa.git
cd toa
cargo build --release -p toa-cli

产物为单文件 target/release/toa（Windows 为 toa.exe），或用 cargo 安装至 PATH：

cargo install --path crates/toa-cli

验证安装：

$ toa --version
toa 0.1.0 (TOA 0.1)

2Git 使用方式

TOA 不依赖 git：toa 自己计算兼容 git 的树哈希。本地库可以是任意目录；公开分享时用 git 仓库最方便。

--git=行为
auto默认：优先用系统 git（2.25+），否则用内置 git。
systemPATH 中的系统 git。
builtintoa 内置 git，支持读库与取对象；定稿仅算文件哈希，提交需系统 git。

3发布库

公开库为 git 仓库，发布分支（默认 main）存对象与库的清单。根目录须置 .gitattributes 按字节原样存储，否则报 E_LIB_ATTRIBUTES：

* -text

含草稿与 .gitattributes 的目录首次发布：

git init -b main
toa seal             # 将草稿定稿为哈希命名对象
toa publish --commit  # 整理清单、提交并做库的检查
git push              # 手动推送（toa 不推送）

toa seal 前可用 toa status 查草稿，--dry-run 预览变更。

4给对象盖时间戳（建议）

时间戳证明能说明一个对象名最晚在某个时间已经存在，可以用来说明谁先公开。盖章时只发出哈希，所以对象公开之前就可以盖。toa 不做证明；建议用 OpenTimestamps 和它的客户端 ots（pip3 install opentimestamps-client），在库外面操作：

n=ckt_876f99c0ddb9fae4aabf6b8b3b7fd59de24e7e2b
s=my-library/ckt/strongarm-comp/sky130-razavi.g1/$n.stamps
# 对象名，不带换行
printf '%s' "$n" > name
# 只发出哈希，写出 name.ots
ots stamp name
# 放在对象旁边，和对象一起发布
mkdir -p "$s" && cp name.ots "$s/20261125-btc.ots"
# 几小时后：补全 name.ots
ots upgrade name.ots
# 换掉原来那份，再发布一次
cp name.ots "$s/20261125-btc.ots"
# 谁都能核对
ots verify -f name "$s/20261125-btc.ots"

不要钱，也不用注册。哈希进了比特币区块，证明才完整，要等几个小时；证明给出的时间精度也是几个小时。核对时用 ots verify，它从你自己的 Bitcoin Core 节点读区块（裁剪节点就够）；也可以用 opentimestamps.org 上的浏览器内核对，那就要信任这个网站。证明只说明名字那时已经存在，不说明对象是谁做的。

用别的证明也行，例如 RFC 3161 时间戳：标准不限制时间戳目录里放什么 (4.3).

5命令

同 toa --help；编号对应标准章节。

对象

toa hash [--sha256] DIR...输出目录树哈希（非合法的对象树无哈希）。 2.2
toa verify [--types] DIR...读文件核对对象树、入口文件、类型前缀与哈希；--types 附加单对象类型规格检查。 7.4
toa seal [DIR] [--dry-run] [--workspace FILE]原子定稿 DIR 下全部草稿：按内容命名，写好来历和来源表；失败则不改文件。 7.1
toa derive NAME|DIR [--tag TAG] [--into DIR] [--dry-run] [--workspace FILE] [--offline] [--allow-host HOST]... [--yes]把对象复制成新草稿，base 指回它。对象按 toa fetch 的方式查找并核对，或直接取自对象目录；除 history.json 外的文件都复制。草稿名为 <prefix>_draft-<tag>，标签取 --tag，否则取入口文件的 name。不需要 git。 3.4
toa unseal NAME [--branch B]将未发布对象及其未发布引用方还原为草稿。 7.1
toa status [--branch B]只读列出草稿、哈希错配、未发布及缺失对象。 7.1

库

toa publish [--to ADDRESS] [--branch B] [--commit [--sign] | --dry-run] [--workspace FILE] [--volumes] [--keep-latest]核对新对象、整理来源表并重建库的清单（无草稿）；--commit 提交并做库的检查（不推送）。最新标记移到新的一代，新的一支也标上；--keep-latest 则保持不变。 7.2
toa latest NAME|PATH... | --all [--off] [--branch B] [--commit [--sign] | --dry-run]在库的清单里把对象标为最新，同一来历中同一支其他代的标记随之去掉；--off 清除标记。--all 给每个还没有标记的一支标上最新的一代，用于 toa publish 开始给标记之前发布的对象。 5.2
toa check [--rev R] [--base B | --no-base] [--branch NAME] [--workspace FILE]以发布分支最新提交为基准，对提交（默认 HEAD）做库的检查。 6.4
toa remove NAME|PATH [--record] [--reason TEXT] [--to ADDRESS] [--keep-notes] [--branch B] [--dry-run]删除对象副本及旁挂文件；--record 留删除记录，指明其他来源。 6.5
toa source check FILE...按发布分支严格规则检查来源表。 5.1

获取与索引

toa fetch NAME... [--into DIR] [--workspace FILE] [--offline] [--allow-host HOST]... [--yes]依次从本机与工作区清单按名取对象，核对后落盘；清单外主机需确认或 --allow-host。 7.3
toa cat NAME PATH [--workspace FILE] [--offline] [--allow-host HOST]...同 toa fetch 定位核对后，输出指定文件至标准输出。
toa index [--workspace FILE] [--out DIR] [--full] [--follow-includes] [--offline] [--allow-host HOST]...扫描工作区清单所含库并建索引（非交互）。 8.2

6选项和退出码

--json标准输出打印 JSON Lines，供脚本与 Agent 用。
-C DIR以 DIR 为工作目录运行。
--git=auto|system|builtin选择 git 实现，见上文。
--version, --help输出版本或帮助。
退出码含义
0成功。
1发现问题。
2用法错误。
3运行失败（缺 git 或文件不可读）。
4取对象失败（未找到、离线或主机未授权）。
