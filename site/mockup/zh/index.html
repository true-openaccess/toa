01 工作原理

五大核心特性

对象不可变

对象是以内容哈希命名的目录：改动一字节即成新对象，原对象不变。

关键命令名称已缩写

将草稿定稿：

toa seal

ckt_draft-razavi → ckt_876f99c0…

复制后将 w=4u 改为 w=5u 并重算哈希：

toa hash copy/

6d99388d… 新对象，新名称

示意图
  • ✓同一对象名在任何时间均指向逐字节相同的内容。
  • i哈希算法同 git，但计算不需要 git：本地对象可放在任意目录，公开分享时用 git 仓库最方便。

对象自组织

对象按名字引用它用到的对象，完整设计可以跨库组装，不需要集中的库表。

toa.yaml节选
type: ckt ifc: ifc_12ad57c5… uses: latch: ifc: ifc_1f0c663d… ckt: ckt_01a3e82c…

高亮行按哈希引用其他对象。

示意图
  • ✓引用写明设计需要的每个部分，不论存在哪个库。toa fetch 按名字逐个取回；自动顺着引用取齐还在计划中。
  • i旁挂来源表只提示去哪里取，取到的内容由对象名核对。

防篡改、防丢失

对象以哈希成链：改写历史会改变后续所有对象名，任意核对过的副本与原件等价。

关键命令名称已缩写

核对对象完整性：

toa verify ckt_876f99c0…/

ok

镜像被篡改 1 字节：

toa verify mirror/ckt_876f99c0…/

error E_NAME_MISMATCHthe files hash to 6d99388d…

示意图
  • +发布提交应当签名，以记下发布者。Software Heritage 等存档的目录标识就是同一个哈希，可证明对象不晚于存档当日已经存在。
  • i无需账本、共识或代币，仅凭哈希链即可实现类区块链防篡改。

Agent 原生

纯文本文件、单一 CLI 与精确对象名，让 Agent 直接读写、定稿并引用设计。

Agent 工作流节选

你 › 把 StrongARM 比较器移植到 gf180。

从电路网表派生草稿：

toa derive ckt_876f99c0… --tag gf180

ckt_876f99c0… → ckt_draft-gf180

修改草稿后定稿：

toa seal

ckt_draft-gf180 → ckt_3f8e21aa…

Agent › 完成：ckt_3f8e21aa…，基于 ckt_876f99c0…

示意图
  • ✓YAML 入口文件、SPICE/Spectre 网表（含 RNL 原理图）与 Markdown 说明，无二进制库与私有 API。
  • i工程师以明文 diff 审阅 Agent 改动，或在 Gazettoa 中浏览。

按类型扩展

类型由前缀与类型规格定义，新增数据类型不改命名、核对与传输规则。

对象名
<prefix>_<40 hex digits>

类型前缀

所有类型通用哈希规则

TOA 0.1

ifc ckt tb evd doc lib lay

lay: 版图（已预留），更多规划中

示意图
  • +签核、硅片实测与表征作为 evd 新种类扩展，不增新类型。
  • ✓未知类型照常取回、核对、保留；x 开头前缀供私有与实验类型用。

02 快速上手

一个入口文件，几条命令

以 StrongARM 比较器展示入口文件与核心命令。

入口文件

ckt_876f99c0…/toa.yaml
type: ckt license: CC0-1.0 ifc: ifc_12ad57c51e8f36cac47a4b8a53f2949315f190f5 name: sky130-razavi form: transistor specifications: {process: sky130} description: The classic StrongARM latch. files: netlist: - strongarm_comp.scs
type对象类型，与对象名前缀一致。
ifc实现的模块定义（必填引用）。
name设计名称，各代沿用（记为 sky130-razavi.g1、.g2 等）。
files同目录网表文件。

命令

输出示例，名称已缩写
# 将草稿定稿为哈希命名对象 $ toa seal ifc_draft-sac -> ifc_12ad57c5… ckt_draft-razavi -> ckt_876f99c0… # 读文件核对对象 $ toa verify ckt/strongarm-comp/sky130-razavi/ckt_876f99c0… ok ckt/strongarm-comp/sky130-razavi/ckt_876f99c0… # 整理清单并提交（不推送） $ toa publish --commit 2 object(s) published this time; … nothing was pushed # 执行库的检查 $ toa check ok HEAD: … # 按名取对象，核对后落盘 $ toa fetch ckt_876f99c0… --into objs ckt_876f99c0… objs/ckt_876f99c0… (from …)

toa 尚未发布，请从源码编译；支持系统或内置 git，本地无需 git。

03 库

库：对象目录加一份清单

本地可用任意目录；发布为 git 仓库后即可按名公开取对象。

目录结构

my-library/ library.source.jsonl 库的清单 ifc/strongarm-comp/ifc_12ad…/ ckt/strongarm-comp/sky130-razavi.g1/ ckt_876f…/ ckt_876f….source.jsonl lib/my-library.g1/lib_…/

每个对象以哈希独立成目录，旁挂来源表指明依赖来源。

最新标记

latest
{"object": "ckt_1ec6…", "label": "strongarm-comp/sky130-razavi.g2", "latest": true, …}

对象不可变，“最新”标在库的清单中：各库指定推荐一代，可随时迁移或撤回。

冻结库

lib
type: lib name: toa-official base: [lib_…] # 上一版本 # 附成员表 members.source.jsonl

定稿含成员表的 lib 对象即可冻结发布；新版用 base 衔接并标 latest。
