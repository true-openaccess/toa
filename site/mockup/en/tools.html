Reference tool

toa CLI

Standalone CLI (Windows, Linux, macOS) implementing TOA 0.1 to hash, verify, seal, publish, and fetch objects. MIT-licensed.

Not released toa 0.1.0 (TOA 0.1)

Prebuilt binaries are not yet available. Build from source below (takes a few minutes).

1Build from source

Requires Rust 1.85+ and cargo (install both via rustup):

git clone https://github.com/true-openaccess/toa.git
cd toa
cargo build --release -p toa-cli

Builds a standalone binary at target/release/toa (toa.exe on Windows). Or install to PATH via cargo:

cargo install --path crates/toa-cli

Verify the build:

$ toa --version
toa 0.1.0 (TOA 0.1)

2Git integration

TOA does not need git: toa computes git-compatible tree hashes itself. A local library can be any directory; a git repository is the easiest way to share one publicly.

--git=Behavior
autoDefault: uses system git (2.25+) if available, otherwise built-in git.
systemSystem git from PATH.
builtinBuilt-in git inside toa for reading and fetching; sealing hashes files only, and committing requires system git.

3Publishing a library

Public libraries are git repositories storing objects and the library list on the publication branch (default: main). Add a root .gitattributes to preserve exact bytes—otherwise library checks fail with E_LIB_ATTRIBUTES:

* -text

First publication from a directory with drafts and .gitattributes:

git init -b main
toa seal             # seal drafts into hash-named objects
toa publish --commit  # update lists, commit, and run library check
git push              # push manually (toa never pushes)

Before toa seal, use toa status to list drafts and --dry-run to preview changes.

4Commands

Matches toa --help; numbers link to standard sections.

Objects

toa hash [--sha256] DIR...Print each directory's tree hash (fails on malformed object trees). 2.2
toa verify [--types] DIR...Verify object directories from files: tree structure, manifest, type/prefix match, and hash. --types adds standalone type-specification checks. 7.4
toa seal [DIR] [--dry-run] [--workspace FILE]Atomically seal all drafts under DIR: name each by its contents, and write its history and source list. 7.1
toa derive NAME|DIR [--tag TAG] [--into DIR] [--dry-run] [--workspace FILE] [--offline] [--allow-host HOST]... [--yes]Copy an object into a new draft whose base names it. The object is found and verified as toa fetch does, or taken from its directory; its files are copied except history.json. The draft is <prefix>_draft-<tag>: the tag is --tag, else the manifest's name. Needs no git. 3.4
toa unseal NAME [--branch B]Revert an unpublished object (and unpublished dependents) back to drafts. 7.1
toa status [--branch B]Read-only summary of drafts, hash mismatches, unpublished objects, and missing published objects. 7.1

Libraries

toa publish [--to ADDRESS] [--branch B] [--commit [--sign] | --dry-run] [--workspace FILE] [--volumes] [--keep-latest]Confirm no drafts, verify new objects, tidy source lists, and rebuild the library list. --commit commits and runs the library check (never pushes). Latest marks move to the new generations, and new series get one, unless --keep-latest. 7.2
toa latest NAME|PATH... | --all [--off] [--branch B] [--commit [--sign] | --dry-run]Mark objects latest in the library list, taking the mark from the other generations of their series in the same lineage; --off clears it. --all marks the newest generation of every series without a mark, for objects published before toa publish gave marks. 5.2
toa check [--rev R] [--base B | --no-base] [--branch NAME] [--workspace FILE]Run library checks on a commit (default: HEAD) against the publication branch tip. 6.4
toa remove NAME|PATH [--record] [--reason TEXT] [--to ADDRESS] [--keep-notes] [--branch B] [--dry-run]Remove an object copy and its sidecar files. --record leaves a removal record pointing to other sources. 6.5
toa source check FILE...Validate source lists against strict publication-branch rules. 5.1

Retrieval & indexing

toa fetch NAME... [--into DIR] [--workspace FILE] [--offline] [--allow-host HOST]... [--yes]Fetch objects by name from local storage, then workspace-list sources, verifying files before writing. Unlisted hosts prompt or require --allow-host. 7.3
toa cat NAME PATH [--workspace FILE] [--offline] [--allow-host HOST]...Locate and verify an object (like toa fetch), then print one file to stdout.
toa index [--workspace FILE] [--out DIR] [--full] [--follow-includes] [--offline] [--allow-host HOST]...Index all libraries included in the workspace list (non-interactive). 8.2

5Options and exit codes

--jsonEmit JSON Lines to stdout for scripts and agents.
-C DIRRun with DIR as working directory.
--git=auto|system|builtinSelect git backend; see Git integration.
--version, --helpPrint tool/TOA version or help.
Exit codeMeaning
0Success.
1Problems found.
2Usage error.
3Runtime error (missing required git or unreadable files).
4Fetch failed (not found, offline, or host disallowed).
