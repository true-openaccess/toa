01 How it works

Five core properties

Objects are immutable

An object is a directory named by its content hash—changing one byte creates a new object without altering the original.

Key commandsabbreviated names

Seal a draft:

toa seal

ckt_draft-razavi → ckt_876f99c0…

Copy, change w=4u to w=5u, and rehash:

toa hash copy/

6d99388d… new object, new name

Diagram
  • ✓Any reference to an object always resolves to the exact same bytes.
  • iUses git's tree hash, but computing it needs no git: local objects can live in any directory, and a git repository is the easiest way to share them.

Objects organize themselves

Objects reference what they use by name, so a full design assembles across libraries without a central library table.

toa.yamlabridged
type: ckt ifc: ifc_12ad57c5… uses: latch: ifc: ifc_1f0c663d… ckt: ckt_01a3e82c…

Highlighted lines reference objects by hash.

Diagram
  • ✓References name every part a design needs, in whichever library it is kept. toa fetch gets each by name; following the references automatically is planned.
  • iA sidecar source list suggests where to fetch dependencies; the names verify what arrives.

Tamper-evident and resilient

Hash-linked references form immutable chains: altering history changes every downstream name, and any verified copy equals the original.

Key commandsabbreviated names

Verify an object:

toa verify ckt_876f99c0…/

ok

A mirror altered one byte:

toa verify mirror/ckt_876f99c0…/

error E_NAME_MISMATCHthe files hash to 6d99388d…

Diagram
  • +Publishing commits should be signed, recording the publisher. Archives such as Software Heritage, whose directory ID is the same hash, show that an object existed by the day it was archived.
  • iBlockchain-like tamper evidence without a ledger, consensus, or token—just content-addressed hashes.

Agent-native

Plain-text files, one CLI to verify and seal, and exact hash names let agents read, edit, and cite designs directly.

Agent workflowabridged

you › Port the StrongARM comparator to gf180.

Derives a draft from the circuit:

toa derive ckt_876f99c0… --tag gf180

ckt_876f99c0… → ckt_draft-gf180

Edits the draft and seals it:

toa seal

ckt_draft-gf180 → ckt_3f8e21aa…

agent › Done: ckt_3f8e21aa…, based on ckt_876f99c0…

Diagram
  • ✓YAML manifests, SPICE/Spectre netlists with RNL schematics, and Markdown notes—no binary database or proprietary API.
  • iEngineers review agent edits as plain-text diffs or browse them in Gazettoa.

Extensible by type

Each type pairs a prefix with a specification, letting new design data join without changing naming, verification, or transport rules.

Object names
<prefix>_<40 hex digits>

type prefix

same hash rule for all types

TOA 0.1

ifc ckt tb evd doc lib lay

lay: layout (reserved); more planned

Diagram
  • +Sign-off, silicon, and characterization extend evd as new kinds, not new types.
  • ✓Tools fetch, verify, and preserve unknown types transparently; x-prefixed types are for private or experimental use.

02 Quick start

One manifest, a few commands

StrongARM comparator manifest and core toa commands.

Manifest

ckt_876f99c0…/toa.yaml
type: ckt license: CC0-1.0 ifc: ifc_12ad57c51e8f36cac47a4b8a53f2949315f190f5 name: sky130-razavi form: transistor specifications: {process: sky130} description: The classic StrongARM latch. files: netlist: - strongarm_comp.scs
typeObject type; matches the name prefix.
ifcImplemented interface (required reference).
nameDesign series name (shown as sky130-razavi.g1, .g2, …).
filesNetlist file in the object directory.

Commands

sample output, shortened names
# seal drafts into hash-named objects $ toa seal ifc_draft-sac -> ifc_12ad57c5… ckt_draft-razavi -> ckt_876f99c0… # verify an object from files $ toa verify ckt/strongarm-comp/sky130-razavi/ckt_876f99c0… ok ckt/strongarm-comp/sky130-razavi/ckt_876f99c0… # update lists and commit (never pushes) $ toa publish --commit 2 object(s) published this time; … nothing was pushed # run library check on commit $ toa check ok HEAD: … # fetch by name and verify before writing $ toa fetch ckt_876f99c0… --into objs ckt_876f99c0… objs/ckt_876f99c0… (from …)

toa is not yet released—build from source. Uses system or built-in git; local sealing and fetching need no git.

03 Libraries

A directory of objects and a list

Use any local directory offline, or publish as a git repository so anyone can fetch objects by name.

Directory

my-library/ library.source.jsonl library list ifc/strongarm-comp/ifc_12ad…/ ckt/strongarm-comp/sky130-razavi.g1/ ckt_876f…/ ckt_876f….source.jsonl lib/my-library.g1/lib_…/

Each hash-named object directory carries a sidecar source list pointing to its dependencies.

Latest mark

latest
{"object": "ckt_1ec6…", "label": "strongarm-comp/sky130-razavi.g2", "latest": true, …}

Because objects are immutable, "latest" lives in the library list—each library marks its recommended generation and can move or clear the mark.

Frozen libraries

lib
type: lib name: toa-official base: [lib_…] # previous release # with members.source.jsonl

Seal a lib object with a members list to snapshot a release; chain releases via base and mark the newest latest.
